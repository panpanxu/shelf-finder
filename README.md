# Shelf Finder

把书架拍成照片传上来，之后输入书名、作者或出版社的关键字，就能在照片上框出那本书。单人使用，没有登录。

术语见 [CONTEXT.md](CONTEXT.md)，识别方案和取舍见 [docs/adr/](docs/adr/)。

## 运行

依赖用 [uv](https://docs.astral.sh/uv/) 管理，需要 Python 3.12。

```bash
uv sync
uv run shelf-finder
```

服务默认监听 `0.0.0.0:8000`，同一局域网里的手机可以直接用浏览器打开，拍照上传。第一次识别时 PaddleOCR 会下载模型文件到 `~/.paddlex/`。

识别一张照片约需一分钟：本机 CPU 上的 PaddleOCR 约 40 秒，内网文本模型合并书脊约 25 秒。上传请求会一直等到识别完成。

搜索时关键字和书脊文字都先统一成简体再比较，所以简体、繁体以及夹杂着个别繁体字的关键字都能搜到。

照片页和搜索结果里每本书后面有一个「豆瓣」链接，点开是豆瓣图书的搜索页。搜索词是「书名 作者 出版社」：书名取书脊文字开头那段（英文书名取到第一个汉字或方括号为止），后面保留中文的作者、译者和出版社，去掉英文书名、括号里的版次、作者前的国籍标注和「著」「译」这类身份词，并统一转成简体。豆瓣对整段书脊原文会返回空结果，对这种形式的搜索词结果最准。手机浏览器打开的是豆瓣手机版搜索页。

每本书有一到三个类型标签，取自一张固定的标签表。标签表由模型通读全部书脊后提出、使用者确认后写入数据库，之后新照片识别出来的书只能从这张表里选标签，没有合适类型的归到「其他」。关键字正好是标签名时，贴着这个标签的书全部命中；首页列出全部标签和各自的书数，照片页和搜索结果里的标签都可以点。标签和书脊文字一样可以在「改」里手工改，重新识别会重新自动贴。

照片页右侧的书脊列表可以手工维护：鼠标移到某一行会出现「改」「插入」「删」。改文字直接保存；要改位置或者插入新的一行，在照片上按住拖出那本书的范围再保存。重新识别会用识别结果替换全部书脊，包括手工改过的行，点之前会提示有几行手改。

## 配置

全部通过环境变量设置：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `SHELF_DATA_DIR` | `data` | 照片和 SQLite 数据库所在目录 |
| `SHELF_HOST` | `0.0.0.0` | 监听地址 |
| `SHELF_PORT` | `8000` | 监听端口 |
| `SHELF_LLM_BASE_URL` | `http://192.168.0.88:8888/v1` | 合并书脊用的 OpenAI 兼容接口 |
| `SHELF_LLM_MODEL` | `DeepSeek-v4.1-Flash-EXL3` | 模型名 |
| `SHELF_LLM_API_KEY` | `EMPTY` | 接口密钥，vLLM 不校验 |

## 部署到 NAS 只做查看

上传和识别留在开发机上做，NAS 上只跑一个不带 OCR 的小镜像，查看、搜索、改名和手工维护书脊都可以用。`SHELF_RECOGNITION=off` 时首页没有上传表单，照片页没有「重新识别」，对应的请求返回 403。

1. 把开发机的 `data/` 目录整个拷到 NAS，比如放到 `/vol1/1000/shelf-finder/data`。里面是照片原图和 SQLite 数据库，拷过去就是全部数据。以后在开发机上传了新照片，再拷一次覆盖即可。
2. 把仓库拷到 NAS（不含 `data/`），在仓库根目录构建镜像，再用 [deploy/compose.yaml](deploy/compose.yaml) 启动，先把其中的宿主路径改成第 1 步的位置：

   ```bash
   docker compose -f deploy/compose.yaml up -d --build
   ```

   飞牛 OS 的 Docker 界面里也可以直接用这个 compose 文件创建项目。
3. 浏览器打开 `http://NAS的IP:8000`。

NAS 上的手改和开发机上的数据是两份，互不同步；下次从开发机拷数据过去会覆盖 NAS 上的改动。

## 发布到 GitHub Pages

GitHub Pages 只能放静态文件，所以发布的是导出的静态站：首页、每张照片一页、一个在浏览器里完成的搜索页，查看、搜索（含标签、繁简、容错）、框选放大和豆瓣链接都和服务端一样，没有上传、识别、改名和编辑。

```bash
uv run shelf-finder export site
git add site
git commit -m "更新静态站"
git push
```

仓库里的 `.github/workflows/pages.yml` 会在 `site/` 有变动时把它发布出去。第一次要在 GitHub 仓库的 Settings → Pages 里把 Source 选成「GitHub Actions」。每次在开发机上传新照片或改过书脊后，重新导出并推送即可。

照片原图会随静态站一起公开。公开仓库的 Pages 任何人都能访问；要只给自己看，仓库必须是私有的，而私有仓库的 Pages 需要 GitHub Pro 或组织账号。

## 测试

```bash
uv run pytest
```

测试直接调用本机 PaddleOCR 和上面的文本模型服务，不做任何模拟，完整跑一遍约三分半钟。样例照片在 `tests/fixtures/`：两张合成书架图带每本书的真实位置，`real_shelf.heic` 是一张 iPhone 拍的真实书架。合成图由 `tests/fixtures/make_shelves.py` 生成。
