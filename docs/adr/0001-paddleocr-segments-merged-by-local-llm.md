# 书脊识别：本机 PaddleOCR 读文字行，代码按书脊走向切段，内网 DeepSeek 文本模型合并同一本书的段并整理文字

书脊识别要同时拿到可靠的文字和每本书的位置。识别分三步：

1. 本机 PaddleOCR 读出每行文字和它的四点斜框。照片入库时先把长边缩到 2000 像素，CPU 上一张约 40 秒；手机原图要 160 秒以上，而书名基本不因缩小丢失。
2. 代码按斜框算出每行的文字走向，两行的中心互相落在对方走向直线附近时归为同一段。书架照片有透视，书脊是斜的，按轴对齐范围重叠来分组会把相邻的书串成一片；按走向共线分组则不会把相邻两本书并在一起，同一套书的不同册也能分开。
3. 内网 `DeepSeek-v4.1-Flash-EXL3`（`http://192.168.0.88:8888/v1`，OpenAI 兼容接口，不接受图片）只看各段的文字和位置，把宽书脊上并排印成几列、被切成几段的同一本书合并起来，并修正 OCR 误识字。调用关闭思考，用 JSON schema 约束输出；模型没有提到的段各自成为一本书。

在一张约 40 本书的 iPhone 书架照片上，整个识别约 65 秒，因此上传仍是同步完成识别。

## Considered Options

- 内网 `deepseek-ocr`（`http://192.168.0.84:8000/v1`）：合成测试图上完美，但在真实书架照片上读到十几行后陷入重复循环，把同一段文字输出几百遍直到 8192 上下文耗尽。n-gram 重复抑制参数在这台服务上无效；重复惩罚能止住循环，但整图只读出 17 行，右半边的书全部丢失；切块识别时同一本书在不同块里读成不同的字。
- 把全部文字行直接交给文本模型归并：一百多行时模型会漏掉行编号，并把同一套的几本细书并成一本。模型看不到照片，在上百组坐标上做几何判断是它的弱项。
- 只用代码切段、不用模型：宽书脊会被拆成几条书脊，误识字也得不到修正。
- 开启文本模型的思考：十行文字的测试上推理 105 秒、耗尽 4000 token 仍未产出答案；关闭思考 3.6 秒且结果正确。
